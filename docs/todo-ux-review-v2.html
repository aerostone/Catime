0 · 先立原则：单编辑器

不先定这个，后面每一项都是头痛医头

当前三个表面都能碰任务：任务列表对话框（真编辑器）、便签卡行（单击改完成、右键菜单改日期/优先级/移动/删除）、托盘 Top5（已改为纯导航，好）。而便签行菜单里的"设置截止日期 / 调整优先级"点进去并不是内联编辑，而是跳去列表对话框（EditInList）——用户感知到的是"两个编辑器"，实际是一个编辑器加一个传送门。这就是"乱"的根。

原则：列表是唯一的增删改入口；便签卡只做展示 + 完成 + 番茄；托盘只做导航。下面 N2、N3 都是这条原则的实例化；接受这条，后面砍功能时才有依据。

N · 便签卡（重灾区，6 项）

src/todo/todo_stickies_window.c + todo_sticky_rowmenu.c + todo_board_render.c + todo_board_layout.h

N1P0

卡片行单击 = 直接切换完成，无悬停、无确认、无撤销

改约 10 行

WM_LBUTTONDOWN → BoardLayout_RowAt → TodoStore_SetDone(toggle)：v1 的 A1（托盘单击完成）修好了，但同一个病搬到了便签卡上，而且更重——便签是常驻桌面、鼠标天天经过的表面。GDI 自绘行没有任何 hover 高亮（无 WM_MOUSEMOVE 跟踪），用户在"点一下看看"时任务就被标完成，下次 push 同步到服务端。完成虽可再点回来，但同步出去的状态收不回。

单击行改为选中高亮（内存态即可），双击或右键菜单才切换完成；至少给行加 hover 底色，让"可点"先被看见再被触发。

N2P0

超高任务被静默裁掉，无"更多"提示

改约 12 行

PaintRows: if (top + ROW_H > rc->bottom) break：卡片没有滚动条，装不下的行直接不画，也没有 +n more 尾行。用户看到"本周 3 件事"，实际有 8 件——比"列表闪空"更坏：闪空至少看得见，裁剪是看不见的丢信息。结合 N1，用户可能对着一个不完整的列表点完成。

画不下时最后一行画 …还有 n 项，双击打开列表（纯文本即可），点击跳列表。卡片永远不能假装"这就是全部"。长远：卡片加滚轮支持（WM_MOUSEWHEEL + 首行偏移）。

N3P1

行右键菜单是"假编辑器"：日期/优先级点完跳列表

删约 20 行（比特性加法便宜）

行菜单 6 项里"设置截止日期 / 调整优先级"实际调用 EditInList（preselect 后打开列表对话框）。用户在卡片上起意、却在另一个窗口落地，上下文（board、滚动位置）全丢。既然都要去列表，不如一开始就去——菜单项在假装自己能做它做不了的事。

执行 §0 原则：行菜单只留 标记完成 / 开始番茄 / 移到便签 / 删除（含确认，已有）；日期与优先级两项删除，改为一项 在列表中编辑…（诚实的中转）。

N4P1

隐藏是一次点击，找回是三次点击

改约 8 行

标题栏最右 18px（BOARD_HIT_CLOSE）点一下整板隐藏；找回要走托盘 → TODO → 便签子菜单 → 勾选该板。18px 热区贴着"打开列表"（20px）和"折叠"（20px），三连击区总宽 58px，触摸板用户极易误触隐藏，然后认定"便签丢了"。tooltip 虽已诚实（取消置顶/保留任务），但不对称成本没变。

三选一（推荐①）：① 隐藏移出标题栏，只留右键菜单；② 隐藏后在原地留 150×32 的"已隐藏"桩（点即回）；③ 至少把隐藏热区从最右（最易误触位）与折叠对调。

N5P1

卡片零键盘支持、无障碍断裂

M · 约 40 行

StickyProc 无 WM_KEYDOWN / WM_GETDLGCODE，行是画出来的不是控件：键盘用户 Tab 不到行、回车切不了完成、方向键动不了。列表对话框是标准控件（键盘可用），卡片是纯鼠标面——同一功能两套可达性。上游番茄主窗口是键盘可用的，fork 功能不应开倒车。

最小可用：卡片获焦时上下键移动"选中行"（复用 N1 的选中态）、空格切换完成、Esc 隐藏。选中态画虚线框或底色（与 hover 共用一套）。

N6P2

"×"字形仍在说谎，tooltip 在替它圆场

改约 6 行

v1-D2 修了一半：tooltip 已诚实（"取消置顶（保留任务）"），但字形还是全平台"关闭"含义的 ×。用户先看到的是字形、不是 tooltip——第一眼仍被误导。

× 改为图钉/眼睛字形（已置顶 ◉ / 点击后隐藏），或与折叠 glyph 统一为线条风（– / ▢ / ≡ / ◉ 一套）。绘制侧 6 行。

L · 任务列表对话框（2 项）

resource/todo_dialog.rc + src/dialog/dialog_todo_list*.c + dialog_todo_boards.c

L1P1

看板管理与任务管理挤在一个对话框

M · RC + 逻辑约 50 行

底部 board 行：combo + New/Rename/Del/Sticky + Close——5 个按钮管"板"，上面 8 个控件管"任务"。用户想加任务，先要越过一排不认识的板按钮（New 是新建任务还是新建板？——是板）。5 秒测试：第一眼不知道这个对话框到底管几件事。v1-B2 修了过滤器分组，但底部又长出第二套管理体系。

板管理收进 combo 旁的一个 … 按钮（弹小菜单：新建/重命名/删除/显示隐藏），默认只留 Board: [combo▾] […] Sticky [x] [Close] 一行。任务区保持唯一视觉主体。

L2P2

同步板上 Add 先弹窗再改存他处，全程打断

改约 10 行

选中同步板时点 Add：MessageBox 告知 pull-only 并改存默认板。信息是对的，但模态弹窗打断了最高频操作（加任务）。用户第三次看到这个框就会烦。

同步板选中时直接禁用 Add 行（edit + due + importance 置灰），行内 cue 写 同步板只读，请切本地便签添加。把"事后解释"变成"事前可见"（同 v1-C1 的修法）。
