A · 托盘 TODO 子菜单

src/tray/tray_menu_todo.c — BuildTodoMenu / HandleTodoMenuRow

A1P1

Top5 行单击 = 直接标为完成，无确认、无撤销

改约 10 行

托盘菜单是误触最高发的表面（TPM_RETURNCMD 下，鼠标一滑一点即触发）。“完成”是一个 destructive 动作：它会写 todo.txt、记 updatedAt、下次 push 同步删除服务端任务。用户只是想看一眼任务，却可能点掉一个任务，且事后无任何反馈（菜单直接消失）。

单击行改为“打开任务列表并选中该行”（导航代替破坏），完成动作只保留在列表对话框和便签里。如果坚持菜单快捷完成，至少改成需要两次点击：第一次选中打勾，第二次确认。

A2P2

“New Task” 与 “Task List…” 同目的地

改约 5 行

CmdTodoNew 与 CmdTodoList 都只是 ShowTodoListDialog。两个菜单项、一个行为，用户会疑惑它们到底有什么区别（官能怀疑“New Task 是不是没生效”）。

二选一：删掉 “New Task”（列表里已有 Add 行）；或让 “New Task” 打开列表后直接聚焦标题输入框，做出真实差异。

A3P2

重要度符号 ‼ / ● 无图例、跨字体渲染不一致

改约 5 行

‼（U+203C）在部分菜单字体下回退到 emoji 字体，● 与正文灰度接近。用户无法从符号反推含义，且与列表对话框的 [!] / [ ] 体系不统一——同一产品两种语言。

统一用列表同款文字符号：高 [!]、中 [B]、低 [C]（或沿用 [ ] 三档粗细），纯文本、任何字体都稳定。

B1P0

“Done:” 标签压住 Due-To 输入框

改 RC 2 行

RC 实测：Due-To 输入框 x=174 w=64（174–238），“Done:” 标签 x=172 w=26（172–198）。重叠 24px，用户看到的是标签文字盖在输入框边框上。这是布局 bug，不是品味问题。

按上面 mockup 的分组方案重排：时间范围独立一行，Done 范围只在 Custom 模式出现，从根上消灭 6 组控件挤一行的局面。

B2P1

11 个过滤控件平铺、无分组，5 秒测试失败

M · RC+ 逻辑约 60 行

第一行 5 组、第二行 6 组，全部同字号同灰度。用户想切“本月”要先理解 Range/Scope/Due From/Due To 四个概念的关系。过滤器是此对话框最高频操作，却是全屏最难扫的一块。

GROUPBOX 分三组（时间范围 / 状态与搜索），Done 日期范围收进 Custom 模式；Scope 默认 Week 不变。控件总数不变，扫读成本降一半。

B3P1

日期框逐字重查：输入中途列表闪空

改约 15 行

EN_CHANGE 触发全量 RefreshList（含 qsort + LB_RESETCONTENT + selected=-1）。用户键入 “2026-0” 的中间态匹配不到任何行，列表闪空；每敲一键闪一次。关键词实时过滤是合理的，日期不是——日期是结构化输入，没有中间态价值。

日期框改失焦（EN_KILLFOCUS）+ 回车触发；关键词保留实时但加 200ms debounce。选择态 selected 不要在过滤刷新时无条件清零（保留同 id 选中）。

B4P2

行信息扁平：只有 High 可见，overdue 无标红，完成无置灰

改约 20 行（LB 仍纯文本）

行格式 “[x]/[!]/[ ] + 日期 + 标题”：Medium/Low 在行内零表达；overdue（ Gau 你排序最靠前的一批）与普通行视觉无差；已完成行与未完成行同色。用户扫列表回答不了“哪件最急”。

不换 owner-draw 也能做：overdue 行前缀 [!] + 标题保持（纯文本框无颜色时，至少 [!] 全覆盖高中低三档：[A]/[B]/[C]），完成行前缀 [x] 保持。等价于把 A3 的符号体系贯穿过来。

B5P2

Close 与 OK 同功能；新建 due 框无格式提示

改约 10 行

Modeless 对话框（CreateDialog）没有“确认/取消”语义：OK 与 Close 都是 DestroyWindow。两个按钮、一个行为（同 A2 的毛病）。另：Add 行的 due 输入框无标签无 cue，用户第一次用只能靠报错 “日期格式 YYYY-MM-DD？” 反推。

删掉 OK，只留 Close；due 框加 EM_SETCUEBANNER “YYYY-MM-DD”；关键词框加 cue “搜索标题…”（B7 的空状态一起做）。

B6P2

全英文硬编码，与托盘本地化脱节

M · 走语言表

Week/Month/Custom、All/Local/Sync、Low+/Medium+、Add/Done/Delete/Pin 全部 L"..." 硬编码，而托盘菜单走了 GetLocalizedString。中文用户看到托盘中文、对话框英文，中英混排。

统一走语言表（至少中英）。这是上游 fork 功能的通病：便签菜单也是 \u 硬编码（见 D7），建议一次扫完。

B7P2

空结果无提示

改约 8 行

过滤到零行时列表全白。用户分不清“同步失败没拉到”还是“本周确实没任务”——结合 B3 的闪空，体验是“列表老是莫名其妙变白”。

rowCount==0 时插一行禁用态占位 “（无匹配任务）”，并在同步未配置时提示 “未配置同步，仅显示本地”。

C · 设置对话框（IDD 800）

src/dialog/dialog_todo_settings.c — FillFromCurrent / CollectAndSave

C1P1

空 backend 时静默吞掉用户的 Enable 勾选

改约 12 行

CollectAndSave 里 `if (!url[0] || !token[0]) en = FALSE`：用户勾上 Enable、点 OK、再打开发现没勾上，全程零解释。用户会重复三次然后认定“这个开关是坏的”。这是典型的反馈缺失（ ski11 章：每个操作都要有可理解的结果）。

URL/Token 为空时直接 disable Enable 复选框，旁边附注 “填写 URL 与 Token 后可用”。把“事后吞掉”变成“事前说清”。

C2P2

同步状态全不可见；Sync Now 点完零反馈

M · 状态行 + 缓存时间戳

三个入口（托盘/列表/设置）都有 Sync Now，但点完之后：成功了？离线了？token 错了？用户只能凭“列表变没变”猜。做双向同步（冲突文件、tombstone、cursor）却不给状态出口，冲突快照落盘了用户也永远不知道。

设置对话框加一行状态文本：“上次同步 12:03 · 成功 / 失败（401）/ 离线”。有 conflict 文件时给一个按钮 “打开冲突目录”。托盘 TODO 标签旁可考虑追加 “(n)” 之外的同步点，但先做对话框这一处即可。

C3P2

同步区与便签区混排、无分隔

改 RC 约 6 行

“Sticky notes stay on top” checkbox 悬在 Sync Now 与 OK 之间，用户会误读为同步相关选项（“置顶同步？”）。对话框标题是 TODO Settings，里面装了两个不相关的域。

两个 GROUPBOX：“同步 (tweek)” / “桌面便签”。长远看便签选项增多（透明度？字号？）时再拆独立页，现在分组即够。

D1P0

标题栏三处绘制重叠

改 render 约 15 行

render.c 实测：①标题文本区 `tr.right -= 30`，但右侧 glyph 实际占 [-]/[+]（~18px）+ x（26px）= 44px 起，标题长了会盖住 glyph；②番茄倒计时 `pr.left += 8` 与标题同一 x 起点，pomodoro 一启动两行字糊在一起（mockup 即现状截意）。26px 高的条子里塞了 4 个元素，没有分区。

标题区 right 收至 -74；倒计时移出标题栏、放到 body 首行（mockup 方案）；glyph 区固定 70px 右对齐。三处分区，互不侵入。

D2P0

右上 “x” 不是关闭，是取消置顶

改约 10 行

WM_LBUTTONDOWN 右上 26px → TodoSticky_SetPinned(FALSE)（隐藏窗口）。全平台约定里 x = 关闭/删除。用户点 x 想关掉便签，实际只是隐藏；更糟的是任务还 pin 着，下次 RestoreAll 又弹出来——“这玩意关不掉”。标签说谎比缺功能更伤信任。

x 改为图钉态表达：已置顶 “◉”、点击后变 “○”（仍隐藏，但符号诚实）+ tooltip “点击取消置顶”。或干脆去掉 x，收起/隐藏只走右键菜单（少一个误触源）。

D3P1

Delete 与 Unpin 相邻、无确认，且直通服务端删除

改约 10 行

右键菜单底部：取消置顶 / 删除任务上下相邻。Delete → Remove → todo.deleted → 下次 push 删服务端（tombstone）。一次手滑 = 本地+服务端双删，conflict 文件是唯一的后悔药，而用户不知道它的存在（见 S1）。

Delete 加确认框（MB_OKCANCEL，“将同时从服务端删除”写清后果）；或把 Delete 移入 “更多…” 二级。确认框在 Win32 上是 5 行代码，别省。

D4P1

折叠手势零可发现性

改约 15 行

双击标题栏收起、[-]/[+] 切换——没有任何 tooltip、hint、菜单之外的入口。Body 有 “双击编辑内容” 的 hint（好），但收起没有。用户永远发现不了，只能你口头教。

便签窗口加 tooltip（标题栏：“双击收起/展开”）；body hint 轮换两条（编辑 / 收起手势）；[-]/[+] glyph 加大点击热区感知（现有 18px 宽对触摸板用户偏小，至少视觉加粗）。

D5P2

右键菜单头缺任务锚点，7 项平铺

改约 12 行

第一项是超长的 “▶ 开始番茄（<完整标题>）”，标题一长菜单被撑宽，后面 6 项跟着遭殃。且用户点开菜单先看到的是动作，而不是“我正在对哪行操作”的确认。

菜单头加一条禁用灰项（任务标题截断 20 字，不可点），动作项精简为 “▶ 开始番茄”。顺序建议：标题（灰）/ 开始番茄 / 标为完成 / — / 展开·置顶·重命名 / — / 删除（垫底，与 D3 的确认框配合）。

D6P2

重要度只靠标题栏颜色，色盲用户无第二信号

改约 6 行

红/橙/绿/灰四色是唯一的 importance 通道（WCAG：不只用颜色传达状态）。红绿色盲用户分不清高 vs 低。

标题前加文字符号 [!] / [B] / [C]（与 A3/B4 同一体系），颜色保留给普通用户。绘制侧 6 行，体系三处统一。

D7P2

便签菜单中文 \u 硬编码（同 B6）

M · 与 B6 一并走语言表

rowmenu.c 全是 L"\u6807\u4e3a\u5b8c\u6210" 这类写法。英文系统用户看到中文菜单，中文用户在托盘看英文（A 系英文）——语言在三个表面之间是随机分布。

与 B6 同一批走 GetLocalizedString。排期上可以和 B6 合并为一个 “本地化补齐” 任务。

S · 跨端（C/S 视角）：冲突与状态没有 UI 出口

todo_sync_merge.c / todo_task_sync — 协议已对，呈现缺席

S1P1

冲突快照只落盘，UI 零入口

M · badge + 打开目录

server-won 时本地 loser 写进 todo.txt.conflict-<ts>——然后呢？没有托盘提示、没有列表 badge、没有入口打开那个目录。从用户视角： “我改的字丢了，且没人告诉我”。双向同步里，冲突可视化与同步本身同等重要。

存在 conflict 文件时：托盘 TODO 标签加 “(!)” 后缀；任务列表顶部插一条提示行，点击打开文件所在目录。清掉文件即清 badge（下次启动/轮询检查）。

S2P2

同步连接态不可见（在线/离线/401/轮询中）

M · 与 C2 合并做

60s 轮询 + mtime 推送，全在后台线程。离线一周的用户以为在同步，token 过期的用户以为没任务。C/S 架构里“连接态”是桌面端的标配（想想 Dropbox 托盘图标的三态）。

与 C2 同一状态源：托盘菜单底加一条禁用灰字 “上次同步 12:03 · 正常”（失败则红字原因）。 merge 线程每次 poll 后写一个内存状态 + 时间戳，菜单构造时读。

建议的动手顺序

批次项理由
P0 热修B1、D1、D2布局重叠与说谎标签，用户每天都会撞见；都在绘制/RC 层，风险小
P1 防丢A1、D3、S1、C1四个都是“数据消失且用户不知情”类；A1 + D3 加确认/改导航，S1 + C1 补反馈
P1 体验B2、B3、D4过滤器分组 + 输入时机 + 手势发现；做完列表和便签才算“能用得顺手”
P2 统一A3、B4、D6（符号体系）、B6、D7（本地化）、B5、B7、C2、C3、D5、S2符号/语言/状态的三线统一，适合一次扫完；可拆两批

说明：符号体系（A3/B4/D6）与本地化（B6/D7）各建议合并为一个任务；C2 与 S2 共用同一状态源，一起做。Mockup 坐标按 RC 文件 1:1 还原，可直接对照实现。
